# Система учёта инвентаря компьютерных классов

Консольное приложение на Python для учёта компьютерного оборудования в колледже.
Проблема, которую решает проект: в колледже теряется информация об оборудовании —
непонятно, что где стоит, в каком состоянии и кто за него отвечает.

## Текущее состояние (Спринт 4)

- Работает полный набор команд: просмотр, добавление, поиск, изменение, удаление.
- Данные хранятся в `data/inventory.json` и переживают перезапуск программы.
- Файл читается при старте и перезаписывается после каждого изменения.
- Отсутствие файла, пустой файл и повреждённый JSON обрабатываются без аварийного завершения.
- Повреждённый файл не теряется: рядом сохраняется копия `inventory.json.corrupt-<дата>`.
- Подготовлен `Dockerfile` для запуска в контейнере.

## Требования

- Python 3.11 или новее
- pytest (для запуска тестов)
- Docker — необязательно, только для контейнерного запуска

## Установка

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate

pip install -r requirements.txt
```

## Запуск

```bash
python main.py
```

## Команды меню

1. Показать оборудование — список всех записей и их количество.
2. Добавить оборудование — новая запись с проверкой полей и уникальности номера.
3. Найти оборудование — поиск по инвентарному номеру или по кабинету.
4. Изменить оборудование — изменить кабинет и состояние записи.
5. Удалить оборудование — удаление с подтверждением.
0. Выход.

## Хранение данных

Записи лежат в `data/inventory.json` в виде списка объектов:

```json
{
  "inv_number": "INV-0001",
  "type": "ПК",
  "name": "Системный блок Lenovo ThinkCentre",
  "room": "204",
  "status": "исправно",
  "date_added": "2024-09-01",
  "responsible": "Иванов И.И."
}
```

Сохранение выполняется после каждой успешной операции: сначала данные пишутся в
`inventory.json.tmp`, затем файл подменяется целиком. Так обрыв программы во время
записи не оставляет наполовину записанный файл.

### Поведение в нестандартных ситуациях

| Ситуация | Поведение программы |
|---|---|
| Файла данных нет (первый запуск) | Программа сообщает об этом и работает с пустым списком; файл создаётся при первом сохранении. |
| Файл пустой | Программа сообщает, что список пуст, и продолжает работу. |
| JSON повреждён | Создаётся копия `inventory.json.corrupt-<дата>`, список начинается с пустого, выводится понятное сообщение. |
| В файле не список, а объект | То же: копия файла и пустой список. |
| В списке есть некорректные элементы | Такие элементы пропускаются, остальные загружаются, выводится количество пропущенных. |
| В записи не хватает полей | Отсутствующие поля заполняются пустыми строками, программа не падает. |

## Тесты

```bash
python -m pytest
```

Сейчас в наборе 27 тестов: логика инвентаря (`tests/test_inventory.py`) и файловое
хранение (`tests/test_storage.py`). Все тесты проходят.

## Запуск в Docker

```bash
docker build -t inventory .
docker run -it --rm -v "%cd%/data:/app/data" inventory
```

Флаг `-v` подключает папку `data`, чтобы записи сохранялись между запусками контейнера.
На учебных компьютерах Docker может быть не установлен — тогда достаточно обычного
запуска через Python.

## Структура проекта

- `main.py` — меню, ввод пользователя и вывод результатов.
- `inventory.py` — модель записи, проверки, поиск, изменение и удаление.
- `storage.py` — чтение и запись JSON, резервные копии, обработка ошибок файла.
- `data/inventory.json` — данные об оборудовании.
- `tests/test_inventory.py` — тесты логики инвентаря.
- `tests/test_storage.py` — тесты файлового хранения.
- `tests/conftest.py` — общая фикстура с временной папкой для тестов.
- `USER_STORIES.md` — требования (User Stories).
- `sprint.md` — журнал спринтов.
- `Dockerfile`, `.dockerignore` — контейнерный запуск.
