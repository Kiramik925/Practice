# User Stories

Формат: «Как [роль], я хочу [действие], чтобы [польза]».

| # | User Story | Критерии приёмки | Статус |
|---|------------|------------------|--------|
| US-01 | Как лаборант, я хочу видеть список всего оборудования, чтобы понимать, что есть в наличии. | Пункт меню «Показать оборудование» выводит все записи; видны номер, тип, наименование, кабинет и состояние. | Готово (Спринт 1) |
| US-02 | Как лаборант, я хочу добавлять новую запись об оборудовании, чтобы вести актуальный учёт. | Можно ввести номер, тип, наименование, кабинет и состояние; запись появляется в списке. | Готово (Спринт 2) |
| US-03 | Как лаборант, я хочу находить оборудование по инвентарному номеру, чтобы быстро узнать его кабинет и состояние. | Поиск по существующему номеру показывает карточку; по неизвестному — «Не найдено». | Готово (Спринт 3) |
| US-04 | Как лаборант, я хочу изменять данные записи (кабинет/состояние), чтобы информация была актуальной. | Можно изменить кабинет и состояние; изменения сохраняются. | Готово (Спринт 3) |
| US-05 | Как лаборант, я хочу удалять запись только с подтверждением, чтобы не терять данные случайно. | Удаление запрашивает подтверждение; после подтверждения запись исчезает из списка. | Готово (Спринт 3) |
| US-06 | Как заведующий кабинетом, я хочу, чтобы данные сохранялись в файл, чтобы они не пропадали после закрытия программы. | После перезапуска записи сохраняются; отсутствие файла не вызывает сбой. | Готово (Спринт 4) |

## Что уточнено в Спринте 4

- Формат хранения: JSON-массив объектов с полями `inv_number`, `type`, `name`, `room`,
  `status`, `date_added`, `responsible`.
- Поведение при первом запуске: программы сообщает об отсутствии файла и работает с
  пустым списком, файл создаётся при первом сохранении.
- Повреждённый файл не удаляется: рядом сохраняется копия `inventory.json.corrupt-<дата>`,
  чтобы данные можно было восстановить вручную.
- Критерии приёмки US-06 дополнены проверкой пустого файла и испорченного JSON.
